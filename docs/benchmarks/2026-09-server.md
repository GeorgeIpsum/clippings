# Server benchmark: 2026-09-23

Performance checks and a real-repository smoke test for the server side, per
Plan 2 Task 16. The two `#[ignore]`d tests in `crates/clippings-core/tests/perf.rs`
measure the spec section 13 budgets; the smoke script,
`scripts/smoke-tillix.py`, runs the release `clippings lsp` server against
the benchmark repository, tilliX.

## Machine

- CPU: Apple M4 Pro, 14 cores (`sysctl -n machdep.cpu.brand_string`, `sysctl -n hw.ncpu`)
- OS: macOS 15.7.4 (Darwin 24.6.0)
- rustc/cargo: 1.96.1
- ripgrep: 15.1.0
- clippings: 0.1.0 (`cargo build --release`)
- Benchmark repo: `~/tilli/tilliX` (not modified — see "tilliX working tree" below)

## Performance tests

`cargo test --release -p clippings-core --test perf -- --ignored --nocapture`,
two rounds:

| Check                                    | Budget  | Round 1  | Round 2  | Result |
| ----------------------------------------- | ------: | -------: | -------: | ------ |
| Scan + decorations, 50,000-line buffer    | < 20 ms | 0.54 ms  | 0.57 ms  | met    |
| View rebuild + diff, 10,000 todos         | < 15 ms | 11.53 ms | 11.43 ms | met    |

Both checks pass comfortably: the 50,000-line scan-and-decorate median is
about 35x under its budget, and the 10,000-todo rebuild-and-diff median is
about 1.3 ms (roughly 10%) under its budget. This is in the same range as
the prototype's reported 0.6-0.8 ms and 12.5 ms on the same machine model.

## tilliX smoke test

`scripts/smoke-tillix.py` (kept in the repo so it can be re-run) builds the
release binary if needed, launches `clippings lsp` over stdio, and drives it
as the LSP client: `initialize` with dynamic watcher registration and the
default tag set (`BUG, HACK, FIXME, TODO, XXX, [ ], QUESTION`, `statusBar:
total`), waits for the first full tree, churns 20 files, sends synthetic
`node_modules` events, then shuts the server down.

### Scan set and todo count

Counted fresh (tilliX changes over time — git worktrees under
`.claude/worktrees` come and go):

| Measurement                                          | Value |
| ------------------------------------------------------ | ----: |
| Scan-set file count (`rg --files ~/tilli/tilliX \| wc -l`) | 1814  |
| `clippings scan` todo count, same tag set               | 489 todos in 83 files |
| LSP server's first-tree todo count (statusBar total)    | 489   |

The LSP server's count matches `clippings scan`'s count exactly (489 == 489).
(The brief's `489` reference figure is from an earlier date and happened to
still match on this run; per the controller's ruling it was re-measured, not
copied — worktrees under `.claude/worktrees` had not moved the count this
time.)

### Time to first tree

**65 ms**, well under the "well under a second" target (and under the
prototype's reported 278 ms figure, on a cold client since the server is a
freshly spawned process each run).

### File-churn latency

Twenty existing admitted source files (`.ts`/`.tsx`/`.js`/`.jsx`/`.py`/`.go`/`.rs`,
picked from the live scan set) each got one appended `// TODO churn N` line,
followed by a single `workspace/didChangeWatchedFiles` notification (type
`Changed`) for all 20 — the way a real client would batch a burst of saves.

| Direction                                    | Latency |
| ---------------------------------------------- | ------: |
| Count rises by 20 after the churn notification | 110 ms  |
| Count returns to baseline after restoring the files and sending the change events again | 111 ms |

Both are well within the sub-second budget the workflow needs for
interactive use, and consistent with the 50 ms event-coalescing window plus
the 50 ms view-rebuild window the scheduler uses internally.

Every file the script edited was restored to its exact original bytes (it
reads each file once before editing, then writes those bytes straight back;
the restore is wrapped in the script's `finally` block so it runs even on
failure).

### `node_modules` — no rescan

A `Created` event was sent for `<tilliX>/node_modules` itself, plus 50
`Created` events for fabricated file paths under it (nothing was created on
disk — the events alone are the test). Listening for one second afterward:

- **0** `clippings/status` notifications arrived at all (`scanning: true` or
  otherwise) — matches the never-index admission rule, which drops paths
  inside `node_modules` before any stat (the directory's own event costs one
  `is_dir`).
- The todo count did not change from the 489 baseline.

Result: **no rescan** — the built-in `node_modules` exclusion (spec's
never-index list) holds under synthetic watched-file events, not just under
a walk.

### Shutdown

`shutdown` request, then `exit` notification: the process exited with code
**0**.

### tilliX working tree

`git -C ~/tilli/tilliX status --porcelain`, captured immediately before and
immediately after the script ran: both empty, byte-identical. The working
tree was not modified beyond the temporary, restored edits described above,
and nothing in tilliX was committed.

## Result vs the performance targets (spec section 13)

- **View rebuild + diff, 10,000 todos, under 15 ms**: met (11.43-11.53 ms
  medians).
- **Scan + decorations, 50,000-line buffer, under 20 ms**: met (0.54-0.57 ms
  medians).
- **Smoke test — todo count matches `clippings scan`, first tree well under
  a second, exit code 0**: all met (489 == 489, 65 ms, exit 0).
- **Churn and `node_modules` checks (controller ruling, not in the original
  brief)**: both met — a 20-file churn round-trips in about 110 ms each way,
  and synthetic `node_modules` events never produce a `scanning: true`
  status or a count change.

No target was missed on this run.
